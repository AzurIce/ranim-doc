Retained animation definition nodes and input/recipe type erasure. Retained definition trees, separate from prepared runtime animation nodes.

AnimDef pairs an input snapshot with a recipe. AnimDefNode keeps those pairs behind DynAnimDef at its leaves and owns child definitions at its branches. Building borrows the entire tree, preparing a fresh AnimNode without replacing any definition with execution data.

use ranim_core::animation::{
    AnimRecipe,
    def_node::{AnimDef, AnimDefNode, AnimDefNodeContent},
    eval::Static,
    node::AnimNode,
};

struct HoldNumber { duration: f64 }
impl AnimRecipe<f64> for HoldNumber {
    fn build(&self, initial: &f64) -> AnimNode {
        AnimNode::from_eval(Static(*initial), self.duration)
    }
}
let mut definition = AnimDefNode::from_recipe(2.0, HoldNumber { duration: 3.0 });
let first = definition.build();
if let AnimDefNodeContent::Leaf(leaf) = &mut definition.content {
    leaf.downcast_mut::<AnimDef<f64, HoldNumber>>().unwrap().recipe.duration = 5.0;
}
let second = definition.build();
assert_eq!(first.duration_secs(), 3.0);
assert_eq!(second.duration_secs(), 5.0);

Playback builders are defined in super::build: AnimDef and AnimDefNode implement Unplaced, parameter builders produce Paramed, and At fixes placement. Converting any of these to AnimDefNode retains the definition. Placement can temporarily build a node to resolve its natural window.
